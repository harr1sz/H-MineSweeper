# Security Policy

## Supported versions

No deployed version is currently declared supported. After a public-access
Alpha release candidate is published, only the latest candidate will be
supported. This is an experimental service, not a public ranked platform or a
service-level agreement.

## Report a vulnerability privately

Do not open a public issue containing exploit details, credentials, private
room data, board seeds, personal data, research identifiers, or raw telemetry.

Use GitHub's private vulnerability reporting flow:

1. Open the repository **Security** tab.
2. Choose **Advisories** and **Report a vulnerability**.
3. Include the affected version or commit SHA, reproduction steps, impact, and
   a minimal proof of concept with secrets removed.

If private vulnerability reporting is temporarily unavailable, do not publish
technical details. Use a private maintainer contact listed by the repository,
if one is available, or wait for the private reporting flow to return.

We will acknowledge a valid report, assess the affected surface, and coordinate
remediation and disclosure. Credential exposure, privacy boundary violations,
and corrupted local results can pause the affected public or research surface.
An incorrect competitive outcome or duel-integrity failure disables and pauses
1v1 only; healthy solo remains available unless the root cause also affects
shared solo logic, privacy, or stored evidence.
